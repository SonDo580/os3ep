# 2: Then, let’s understand how linear page table size changes as page size grows. Before running any of these, try to think about the expected trends. How should page-table size change as the address space grows? As the page size grows? Why not use big pages in general?

```bash
./paging-linear-translate.py -P 1k -a 1m -p 512m -v -n 0
# ARG address space size 1m
# ARG phys mem size 512m
# ARG page size 1k
# ...
# -> page_table_size = address_space_size / page_size = 1024

./paging-linear-translate.py -P 2k -a 1m -p 512m -v -n 0
# ARG address space size 1m
# ARG phys mem size 512m
# ARG page size 2k
# ...
# -> page_table_size = 512

./paging-linear-translate.py -P 4k -a 1m -p 512m -v -n 0
# ARG address space size 1m
# ARG phys mem size 512m
# ARG page size 4k
# ...
# -> page_table_size = 256
```

- Page table size:
  - increases when address space grows.
  - decreases when page size grows.
- **Why not use big pages**:
  - needs a large contiguous chunk of free physical memory.
  - must swap large amount of data between RAM and disk.
  - a process only needs a small amount of memory but gets a big chunk _(internal fragmentation)_.

```bash
./paging-linear-translate.py -P 1k -a 16k -p 32k -v -u 50
# ARG address space size 16k
# ARG phys mem size 32k
# ARG page size 1k
# ...
# The format of the page table is simple:
# The high-order (left-most) bit is the VALID bit.
#   If the bit is 1, the rest of the entry is the PFN.
#   If the bit is 0, the page is not valid.
# ...
# Page Table (from entry 0 down to the max size)
#   [       0]  0x80000018
#   [       1]  0x00000000
#   [       2]  0x00000000
#   [       3]  0x8000000c
#   [       4]  0x80000009
#   [       5]  0x00000000
#   [       6]  0x8000001d
#   [       7]  0x80000013
#   [       8]  0x00000000
#   [       9]  0x8000001f
#   [      10]  0x8000001c
#   [      11]  0x00000000
#   [      12]  0x8000000f
#   [      13]  0x00000000
#   [      14]  0x00000000
#   [      15]  0x80000008

# Virtual Address Trace:
#   VA 0x00003385 (decimal:    13189)
#   . vpn = (va & vpn_mask) >> shift
#         = (0x00003385 & 0x00003c00) >> 10
#         = 0x00003000 >> 10 = 0x0000000c (decimal: 12)
#     MSB = 1 (valid) -> pfn = 0x0000000f
#   . offset = va & offset_mask
#            = 0x00003385 & 0x000003ff
#            = 0x00000385
#   . pa = (pfn << shift) | offset
#        = (0x0000000f << 10) | 0x00000385
#        = 0x00003f85
#
# (Other VAs: similar)
```

- **Formula:**

```
page_size = 1024 (1k) = 2^10
-> lower 10 bits represent offset
-> offset_mask = 0x000003ff (... 0000 0011 1111 1111)
   shift = 10

page_table_size = address_space_size / page_size = 16k / 1k = 16
-> higher 4 bits represent virtual_page_number
-> vpn_mask = 0x00003c00 (... 0011 1100 0000 0000)

virtual_page_number = (virtual_address & vpn_mask) >> shift
offset = virtual_address & offset_mask
physical_address = (physical_frame_number << shift) | offset

(page_size = 2^k; k = shift
 virtual_page_number = virtual_address // page_size
 offset = virtual_address % page_size
 physical address = physical_frame_number * page_size + offset)
```

- **Trend:** increase the percentage of pages that are allocated in each address space -> more valid page table entries.
