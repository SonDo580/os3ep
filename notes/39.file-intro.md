- A **persistent-storage** device stores information permanently (for a long time).

# Files and Directories

- 2 keys abstractions in virtualization of storage: **file** and **directory**.

## File

- A file is a linear array of bytes.
- Each file has some kind of **low-level name**, called its **inode number (i-number)**.
- The OS does not know about the structure of the file. The file system simply store such data persistently on disk and make sure the data is the same when you request it again.
- File **extension** is a **convention** to indicate file **type**.

## Directory

- A directory also has a low-level name (an inode number).
- Content: It contains a list of (user-readable name, low-level name) pairs.
- Each entry refers to a file or another directory. By placing directories within other directories, users can build an arbitrary **directory tree** (**directory hierarchy**).
- The directory hierarchy starts at a root directory and uses some kind of **separator** to name subsequent **sub-directories**.
- We can refer to a file by its **absolute pathname**.
- Directories and files can have the same name as long as they are in different locations in the file system tree.

## File system

- Provide a convenient way to **name** all files we are interested in.
- In Unix systems, the file system provides a unified way to access files on disks, other devices, and other things.

# Creating files

- Use `open()` system call.
- `open()` returns a **file descriptor**.
- A FD is an integer, private per process, and is used in Unix systems to access files. Once a file is opened, you use the descriptor to read or write it. This way, a FD represents a **capability**.
- File descriptors are managed by the OS on a per-process basis. This means some kind of structure is kept in the `proc` structure. On xv6:

```c
struct proc {
    // ...
    struct file *ofile[NOFILE]; // Open files
    // ...
};
```

# Reading and writing files

- Useful tool to trace system calls: `strace`.
- Each running process already has 3 files open: standard input, standard output, standard error - represented by file descriptors 0, 1, 2.
- Example: `cat`
  - Open the file for reading.
  - Use `read()` system call to repeatedly read bytes from the file.
  - Use `write()` system call (through library routine `printf()`) to write to standard output.
  - When `read()` returns 0, use `close()` to close the file.

# Reading and writing, but not sequentially

- `lseek()`: Useful to read or write to specific offset within a file.
- For each file a process opens, the OS tracks a current offset to determine where the next read or write will begin.
- To update the file offset:
  - implicit: when reading/writing N bytes.
  - explicit: with `lseek()`.
- The offset is kept in `struct file`, as referenced from `struct proc`. On xv6:

```c
struct file {
    int ref;
    char readable;
    char writable;
    struct inode *ip;
    uint off; // <-
};
```

- **Aside**: Calling `lseek()` doesn't perform a disk seek. It just changes the variable. A disk seek occurs when the subsequent read or write is not on the same track.
- These file structures represent all of currently opened files in the system. Together, they are referred to as the **open file table**. In xv6:

```c
struct {
    struct spinlock lock;
    struct file file[NFILE];
} ftable;
```

- Open the same file multiple times -> Each has a different descriptor and refers to a different entry in the open file table -> Offset is updated independently.

# Shared file table entries: `fork()` and `dup()`

- There are a few cases where an entry in the open file table is shared.
  - A parent process creates a child process with `fork()`.
  - The `dup()` system call (and `dup2()`, `dup3()`).

## `fork()`

- The parent and the child share the open files _(when `fork()` is called)_.
- When a file table entry is shared, its **reference count** is incremented. Only when both processes close the file (or exit) will the entry be removed.

## `dup()`

- The `dup()` system call allows a process to create a new file descriptor that refers to the same underlying open file as an existing descriptor.
- Useful when writing a Unix shell and perform operations like output redirection.

# Writing immediately with `fsync()`

- The file system, for performance reason, will **buffer** writes in memory for some time (5s, 30s,...); after that, the writes will actually be issued to the storage device.
- From the perspective of the application, writes seem to complete quickly. But in rare cases data will be lost _(the machine crashes after the `write()` call but before the write to disk)_.
- Some applications _(like a database management system)_ require the ability to force writes to disk.
- `fsync(int fd)`:
  - The file system will force all **dirty** data to disk.
  - `fsync()` returns once all of these writes are complete.
  - You may also have to `fsync()` the directory that contains the file.

# Renaming files

- Command line tool: `mv`.
- `mv` uses the system call `rename()`.
- `rename()` is an **atomic** call with respect to system crashes -> critical for applications that require an atomic update
  - Example: write out the new version of the file under a temporary name, force it to disk with `fsync()`, then rename the temporary file to the original file's name.

# `mmap()`

- Memory mapping is an alternative way to access persistent data in files.
- The `mmap()` system call creates a corresponding between byte offsets in a file (the **backing file**) and virtual addresses in the calling process (the **in-memory image**).
- The process can then accessing the backing file using CPU instructions (load and store) to the in-memory image.
- File-backed memory mappings support a software abstraction called **persistent memory**.

# Getting information about files

- The file system keeps information about each file it is storing. Such data is called **metadata**.
- To see the metadata of a file, use `stat()` or `fstat()` system calls. These call fill a `stat` structure.
- Command line tool: `stat`.
- Information about each file: size, inode number, ownership, accessed/modified time, ...
- Each file system usually keeps these information in a structure called an **inode**. All inodes reside on disk; a copy of active ones are usually cached in memory.

# Removing files

- Command line tool: `rm`
- `rm` uses the `unlink()` system call.

# Making directories

- A set of directory-related system calls allow you to make, read, delete directories.
- You can never write to a directory directly. You can only update a directory indirectly by creating files and directories.
- Create a directory: Use `mkdir()` system call.
- Command line tool: `mkdir`.
- An empty directory has 2 entries:
  - The '.' directory refers to itself.
  - The '..' directory refers to its parent.

# Reading directories

- Command line tool: `ls`.

```c
// Directory entry
struct dirent {
  char d_name[256]; // filename
  ino_t d_ino; // inode number
  off_t d_off; // offset to the next dirent
  unsigned short d_reclen; // length of this record
  unsigned char d_type; // type of file
}

int main() {
  DIR *dp = opendir(".");
  assert(dp != NULL);
  struct dirent *d;
  while ((d = readdir(dp)) != NULL) {
    printf("%lu %s\n", (unsigned long) d->d_ino, d->d_name);
  }
  closedir(dp);
  return 0;
}
```

- Use 3 calls: `opendir()`, `readdir()`, `closedir()`.
- A program may want to call `stat()` on each file to get more information on each _(This is what `ls` does when passing the `-l` flag)_.

# Deleting directories

- Command like tool: `rmdir`.
- Use system call `rmdir()`.
- Removing directories is more dangerous, as you could potentially delete a large amount of data -> `rmdir()` has the requirement that the directory be empty.

# Hard links

- The `link()` system call creates another way to refer to the same file _(another name that points to the same inode number)_.
- Command line tool: `ln`.
- Why `unlink()` is called `unlink()`:
  - Create a file: Make a structure (the inode) that tracks information about the file. Link a human-readable name to that file, and put the link into a directory.
  - Remove a file: Call `unlink()`. When the file system unlinks file, it decrements the **reference count** (**link count**) to the given inode number. When the reference count reaches 0, the file system also free the inode and related data blocks.

# Symbolic links (soft links)

- Limitations of hard links:
  - You can't create 1 to a directory _(prevent creating cycles in the directory tree)_.
  - You can't hard link to files in other disk partitions _(inode numbers are only unique within a particular file system, not across file systems)_.
- Command line tool: `ln -s`.
- A symbolic link:
  - Is a file itself, of a different type.
  - Formed by holding the pathname of the linked-to file as data.
- **Dangling reference**: removing the original file causes the link to point to a pathname that no longer exists.

# Permission bits & Access control lists

- Files are commonly shared among different users and processes.

## Permissions bits

- Check: `ls -l <file>`.
- Consists of 3 groupings, each has 3 bits (rwx): what the **owner**/**group**/**other** can do.
- The owner of the file can readily change the permissions: Use the `chmod` command to change the **file mode**.
- Execute bit:
  - For regular files, it determines whether a program can be run or not.
  - For directories, it enables changing directories (`cd`) into the given directory.
- Writable bit:
  - For directories, it enables creating files.

## Access control lists

- Enables a user to create a very specific list of who can and cannot read/write/execute/... a set of files.

# Making and mounting a file system

- How to assemble a full directory trees from many underlying file systems?
  - Make the file systems.
  - Mount them.
- To make a file system, use the `mkfs` tool. It writes an empty file system onto the given disk partition.
- To make the file system accessible, use the `mount` program (which uses the system call `mount()`). It takes an existing directory as a target **mount point** and pastes the new file system onto the directory tree at that point.
- See what is mounted on your system: `mount`.

# Key terms

- A **file** is an array of bytes. It has a unique _(within a disk partition)_ low-level name - the inode number (i-number).
- A **directory** is a collection of (human-readable name, low-level name) pairs. Each entry refers to another directory or a file. Each directory also has a low-level name (the i-number). A directory always has 2 special entries: the '.' entry, which refers to itself, and the '..' entry, which refers to its parent.
- A **directory tree** or **directory hierarchy** organizes all files and directories into a large tree, starting at the **root**.
- To access a file, a process must use the system call `open()` to request permission from the OS. If permission is granted, the OS returns a **file descriptor**, which can then be used for read and write.
- Each file descriptor is private per process, and refers to an entry in the **open file table**. The entry tracks the file, **current offset**, and other information.
- Calls to `read()` and `write()` update the current offset. Processes can also use `lseek()` to set its value.
- To force updates to persistent storage, a process must use `fsync()`. Doing so correctly while maintaining performance is challenging.
- To have multiple human-readable names in the file system refer to the same underlying file, use **hard links** or **symbolic links**. Deleting a file is performing the last `unlink()`.
- Most file systems have mechanisms to enable and disable sharing, including **permission bits** and **access control lists**.
