# Problem

- Simple array-based page tables (linear page tables) take up too much memory.

# Simple solution: Bigger pages

- Problem: big pages lead to waste within each page (**internal fragmentation**)
- Thus, most systems use relatively small page sizes in the common case (example: 4KB in x86).
- Support for large pages is often exploited by programs such as a **database management system** (DBMS), which have certain structures that are both large and randomly-accessed.

# Hybrid approach: Paging and segments

- **Problem of linear page tables**: For sparse address space, most of the page table is unused, full of **invalid** entries.

## Idea

- Instead of having a single page table for the entire address space, have 1 per logical segment.
- Have some pairs of **base** and **bound** (or **limit**) registers in the MMU.
  - base: hold physical address of the page table for a segment.
  - bound: indicate end of 1 page table (how many valid pages it has).
- On a context switch, these registers must be changed.

## Algorithm (find PTE on TLB miss)

```python
# Example: 32-bit virtual address space, 4KB pages, 4 segments (00 is unused, 01 for code, 10 for heap, 11 for stack).
# -> Virtual address:
#    . virtual_addr[30..31]: segment
#    . virtual_addr[16..29]: VPN
#    . virtual_addr[0..15]: offset

SEGMENT_MASK = (1 << 31) | (1 << 30)
SEGMENT_SHIFT = 30
VPN_MASK = ((1 << 30) - 1) & (1 << 16)
VPN_SHIFT = 16
# OFFSET_MASK = (1 << 16) - 1

segment = (virtual_addr * SEGMENT_MASK) >> SEGMENT_SHIFT
vpn = (virtual_addr * VPN_MASK) >> VPN_SHIFT
pte_addr = Base[segment] + vpn * sizeof(PTE)
# Check against Bound[segment]
```

## Problems

- Not flexible: segmentation assumes a certain usage pattern of the address space.
- If we have a large but sparsely used segment, we still have page table waste.
- External fragmentation: page tables now can be of arbitrary size, finding space for them in memory is more complicated.

# Multi-level page tables

## Idea: Turn the linear page table into a tree

- Chop up the page table into page-sized units.
- If an entire page of PTEs is invalid, don't allocate that page of the page table at all.
- To track whether a page of the page table is valid (and if valid, where it is in memory), use a new structure called **page directory**.
- In a simple 2-level table, the page directory contains 1 entry per page of the page table. The entry is called **page directory entry** (PTE).
- A PDE minimally has:
  - valid bid: if the PDE is valid, at least 1 PTE in the page of the page table that current PDE points to is valid.
  - page frame number (PFN): combined with **page directory base pointer** (PDBR) to get physical address of corresponding page of page table (or next-level page directory).

## Advantages

- Only allocate page-table space in proportion with amount of address space using.
- If carefully constructed, each portion of the page table fits neatly within a page, making it easier to manage memory.
  - OS can just grab the next free page when allocating/growing the page table.
  - Whereas the linear page table must reside contiguously in physical memory -> harder to find space.

## Costs

- On a TLB miss, 2 loads from memory will be required to get the right translation (1 for the PDE, 1 for the PTE):
  - Assume 2-level page table.
  - Example of time-space tradeoff: Smaller tables, but more operations. Although in common case (TLB hit), performance is identical.
- Complexity (implementation):
  - More involved than a simple linear page table lookup.

## Example: 2-level page table

**Assumptions**:

- Address space: 16KB (2^14) -> 14-bit virtual address.
- Page size: 64B (2^6) -> 6 bits for offset, 14-6=8 bits for VPN.
- A linear page table would have 2^8 = 256 entries.
  Assume each PTE is 4B.
  -> Page table size: 256 \* 4 = 1KB.
  -> Page table can be divided into 1kB / 64B = 16 pages.
  Each page hold 64 / 4 = 16 PTEs.
- The page directory needs 1 PDE per page of the page table -> 16 (2^4) entries.
  -> need highest 4 bits of the VPN to index into the directory.

**Address translation**:

- Extract the **page directory index** (PDIndex) from VPN (highest 4 bits).
- Find address of the page directory entry (PDE):
  `PDEAddr = PageDirBaseRegister + (PDIndex * sizeof(PDE))`
- Fetch and examine the PDE:
  - if PDE is invalid, raise exception.
  - otherwise, continue.
- Extract the **page table index** (PTIndex) from VPN (remaining 4 bits).
- Find address of the page table entry (PTE) from the page of the page table pointed to by the PDE:
  `PTEAddr = (PDE.PFN << SHIFT) + (PTIndex * sizeof(PTE))`
  - where SHIFT = 6 (page size = 2^6)
- Fetch and examine the PTE:
  - if PTE is invalid or user doesn't have access, raise exception.
  - otherwise, continue.
- Find physical address:
  `PhysicalAddr = (PTE.PFN << SHIFT) + offset`

## Translation process (2 levels)

```python
vpn = (virtual_addr & VPN_MASK) >> SHIFT
success, tlb_entry = TLBLookup(vpn)

if success: # TLB hit
  if CanAccess(tlb_entry.protect_bits):
    offset = virtual_addr & OFFSET_MASK
    physical_addr = (tlb_entry.pfn << SHIFT) | offset
    register = AccessMemory(physical_addr)
  else:
    raise Exception(PROTECTION_FAULT)

else: # TLB miss
  # get page directory entry
  pd_index = (VPN & PD_MASK) >> PD_SHIFT
  pde_addr = PDBR + (pd_index * sizeof(PDE))
  pde = AccessMemory(pde_addr)

  if not pde.valid:
    raise Exception(SEGMENTATION_FAULT)
  else:
    # fetch PTE from page table
    pt_index = VPN & PT_MASK
    pte_addr = (pde.pfn << SHIFT) + (pt_index * sizeof(PTE))
    pte = AccessMemory(pte_addr)

    if not pte.valid:
      raise Exception(SEGMENTATION_FAULT)
    else if not CanAccess(pte.protect_bits):
      raise Exception(PROTECTION_FAULT)
    else:
      TLBInsert(vpn, pte.pfn, pte.protect_bits)
      RetryInstruction()
```

## More than 2 levels

- Goal: Make each piece of the page table fit within a single page -> each piece is pointed to by a page directory entry.
- What if the page directory get too big -> add extra levels.

# Inverted page tables

- Instead of having many page tables (1 per process of the system), keep a single page table that has an entry for each physical page of the system.
- Each entry tells us which process is using this page, and which virtual page of that process maps to this physical page
- Finding the correct entry is now a matter of searching through this data structure. A linear scan would be expensive, thus a hash table is often built over the base structure to speed up lookups (lookup physical frame number by process + virtual page number).

## Extra: What if multiple processes share 1 page

- Method 1: Each entry is a linked-list.
- Method 2: Handle shared memory separately before hitting the inverted page table.

# Swapping the page tables to disk

- Some systems place page tables in **kernel virtual memory**, allowing the system to **swap** some portions of these page tables to disk when memory pressure is high.
