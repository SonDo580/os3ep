# 2 approaches to solve space-management problems

- Chop space up into variable-sized pieces.
  - Examples: **segmentation** in virtual memory.
  - Problem: the space becomes fragmented.
- Chop space up into fixed-sized pieces.
  - In virtual memory, this is called **paging**.

# Paging

- Instead of splitting up a process's address space into some number of variable-sized logical segments (code, heap, stack,...), divide it into fixed-size units, each called a **page**.
- View physical memory as an array of fixed-sized slots call **page frames**; each can contain a single virtual-memory page.

# Overview

- To place an address space, OS just finds enough free pages.
- To record where each virtual page is placed in physical memory, OS keeps a per-process data structure known as **page table**.
- Page table: store **address translations** for virtual pages.

# Address translation

- Address space size is 2^n, page size is 2^m (m < n)
  - needs n bits for each virtual address
  - the highest (n - m) bits represent **virtual page number** (VPN)
  - the lower bits represent **offset** (which byte of the page)
- Look up **physical frame/page number** (PFN/PPN) in the **page table** with VPN.
- Combine PFN and offset to get physical address.

# Where are page table stored

- Example:

```
- Assume 32-bit address space, 4KB pages
  -> virtual address = 20-bit VPN + 12-bit offset
  -> need 2^20 translations
- Assume 4 byte per page table entry (PTE)
  -> need 4*2^20 = 4MB of memory for each page table
- Assume there are 100 processes running
  -> need 100*4 = 400MB of memory just for address translations
```

- Because page tables are so big, they are stored **in memory** instead of on-chip hardware in the MMU.

# What's in the page table

## Data structure:

- The simplest form is called **linear page table**, which is just an array.
- The OS indexes the array by the virtual page number (VPN), and looks up the page table entry (PTE) at that index to find the desired physical frame number (PFN).

## **Contents of each PTE**:

- PFN
- **valid bit**: indicate if the translation is valid
  - unused space between heap and stack will be marked invalid.
  - remove the need to allocate physical frames for those pages
- **protection bits**: whether the page could be read from, written to, or executed from.
- **present bit**: whether the page is in physical memory or on disk (has been **swapped out**)
- **dirty bit**: whether the page has been modified since it was brought into memory.
- **reference bit (accessed bit)**: whether a page has been accessed.
  - useful in determining which pages are popular and should be kept in memory (critical during **page replacement**).

## Invalid access

- Generate a trap to the OS, which will likely terminate the process.

# Paging: also too slow

- For every memory reference (instruction fetch or explicit load/store), paging requires us to perform 1 extra memory reference to fetch the translation from the page table.
- Pseudocode:

```python
# Example:
# - virtual address space: 2^6 = 64B
#   page size: 2^4 = 16B
# -> virtual address: 2 MSBs represent VPN, low 4 bits represent offset
#
# - Assume that a single page-table-base register (PTBR) contains the physical address of the starting location of the page table.

VPN_MASK = (1 << 5) | (1 << 4)
SHIFT = 4
OFFSET_MASK = (1 << 4) - 1

# Extract VPN from virtual address
vpn = (virtual_addr & VPN_MASK) >> SHIFT

# Form the address of page table entry (PTE)
pte_addr = PTBR + (vpn * sizeof(PTE))

# Fetch the PTE
pte = access_memory(pte_addr)

# Check if process can access the page
if pte.valid == False:
  raise Exception(SEGMENTATION_FAULT)
if can_access(pte.protect_bits) == False:
  raise Exception(PROTECTION_FAULT)

# Access OK -> form physical address and fetch
offset = virtual_addr & OFFSET_MASK
physical_addr = (pte.pfn << SHIFT) | offset
register = access_memory(physical_addr)
```
