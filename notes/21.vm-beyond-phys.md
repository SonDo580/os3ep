# Problem

- Support multiple large address spaces (aren't fit entirely in memory).
- Solution: Swap portions of address spaces that aren't currently in great demand to disk.

# Swap space

- Reserved space on disk for swapping pages from/to memory.
- To read/write from/to swap space (in page-sized units), the OS needs to remember the **disk address** of a given page.
- Note: swap space is not the only on-disk location for swapping traffic.
  - Example: run program binary (ls, ./main, ...) -> code pages of these binaries are initially on disk -> when the program runs, they are loaded into memory -> if the system needs to make room in physical memory for other needs, it can safely reuse memory space for these code pages.

# Present bit

## What happen on a memory reference (assume hardware-managed TLB, 1-level page table)

- The running process generate virtual memory references (instruction fetches, data accesses).
- Hardware extracts the VPN, checks the TLB for a match (TLB hit), and if a hit, produces the resulting physical address and fetches it from memory.
- If the VPN is not found in the TLB (TLB miss), hardware locate the page table in memory (using the page table base register) and looks up the page table entry (PTE) using the VPN as an index.
- If the page is valid, the hardware extract the PFN from the PTE, installs it in the TLB, and retries the instruction, this time hitting a TLB hit.

## Extra machinery for swapping pages to disk

- Each page table entry needs an extra bit called **present bit**:
  - `present_bit` = 1: the page is present in physical memory
  - `present_bit` = 0: the page is on disk.
- The act of accessing a page that is not physical memory is referred to as **page fault**.
- Upon a page fault, the OS is invoked to handle it. The **page-fault handler** runs and service the page fault.

# Page fault

- Most system handle page faults in software (OS).
- How does the OS know where to find the desired page: Use the bits in the PTE normally used for data such as physical frame number (PFN) for the disk address.
- When the disk I/O completes, the OS updates the page table to mark the page as present, update the PFN field of the PTE to record in-memory location of the newly-fetched page, and retry the instruction.
- The next attempt generates a TLB miss, which would then be serviced and update the TLB will the translation (We could alternately update the TLB when servicing the page fault to avoid this step).
- A last retry would find the translation in the TLB and proceed to access memory at the translated physical address.

# What if memory is full

- To **page in** pages from swap space, the OS may need to **page out** some pages to make room -> **page-replacement policy** (later).

# Page fault control flow

## Hardware

```python
vpn = (virtual_addr & VPN_MASK) >> SHIFT
success, tlb_entry = TLBLookup(vpn)

if success: # TLB hit
    if CanAccess(tlb_entry.protect_bits):
        offset = virtual_addr & OFFSET_MASK
        physical_addr = (tlb_entry.pfn << SHIFT) | offset
        register = AccessMemory(physical_addr)
    else:
        raise Exception(PROTECTION_FAULT)

else: # TLB miss
    pte_addr = ptbr + (vpn * sizeof(PTE))
    pte = AccessMemory(pte_addr)
    if not pte.Valid:
        raise Exception(SEGMENTATION_FAULT)
    elif not CanAccess(pte.protect_bits):
        raise Exception(PROTECTION_FAULT)
    elif pte.present:
        # assume hardware-managed TLB
        TLBInsert(vpn, pte.pfn, pte.protect_bits)
        RetryInstruction()
    elif not pte.present:
        raise Exception(PAGE_FAULT)
        # then the OS runs the page-fault handler
```

## Software

```python
pfn = FindFreePhysicalPage() # to swap page in
if pfn == -1: # no free page found
    pfn = EvictPage() # replacement algorithm

# read page from disk into physical memory
DiskRead(pte.disk_addr, pfn) # sleep (wait for I/O)

# update page table entry
pte.present = True
pte.pfn = pfn

RetryInstruction()
```

# When replacements really occur

- The OS proactively keeps a small portion of the memory free, instead of waiting until the memory is entirely full.
- Most operating systems have some kind of high watermark (HW) and low watermark (LW). When the OS notices that there are fewer than LW pages available, a background thread that is responsible for freeing memory runs. The thread evicts pages until there are HW pages available. The background thread (often called **swap daemon** or **page daemon**) then goes to sleep.
- By performing multiple replacements at once, new performance optimizations are possible.
  - Example: Many systems will **cluster** or **group** pages and write them out at once to the swap partition, thus increasing the efficiency of the disk (reduces seek and rotational overhead of a disk).
