# Problem

- A thread needs to check whether a **condition** is true before continuing its execution.

## Example: a parent thread need to check whether a child thread has completed before continuing (a `join()`)

```c
// - 'volatile' forces reading from memory.
// - Without it, the compiler can optimize by reading 'done' into a register, which leads to infinite loop.
volatile int done = 0;

void *child(void *arg) {
    printf("child\n");
    done = 1;
    return NULL;
}

int main() {
    printf("parent: begin\n");
    pthread_t c;
    Pthread_create(&c, NULL, child, NULL);

    while (done == 0)
        ; // spin

    printf("parent: end\n");
    return 0;
}
```

- This solution is too inefficient: The parent spins and wastes CPU time.

# Condition variable

- To wait for a condition to become true, a thread can make use of a **condition variable**.
  - It is a queue that threads can put themselves on when some state (the **condition**) is not as desired (by **waiting** on the condition).
  - When some other thread changes said state, it can wake one (or more) waiting threads (by **signaling** on the condition).
- A condition variable has 2 associated operations:
  - `wait()`: is executed when a thread wishes to push itself to sleep.
  - `signal()`: is executed when a thread has changed something and thus wants to wake a sleeping thread waiting on this condition.
- POSIX calls:

```c
pthread_cond_wait(pthread_cond_t *c, pthread_mutex_t *m);
pthread_cond_signal(pthread_cond_t *c);
```

- Note that `wait()` also takes a mutex:
  - It assumes that this mutex is locked when `wait()` is called.
  - `wait()` releases the lock and put the calling thread to sleep (atomically). When the thread wakes up _(after some other thread has signaled it)_, it must re-acquire the lock before returning to the caller.
  - This complexity is to prevent certain race conditions.

## Solution to `join()`

```c
int done = 0;
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t c = PTHREAD_COND_INITIALIZER;

void thr_exit() {
    Pthread_mutex_lock(&m);
    done = 1;
    Pthread_cond_signal(&c);
    Pthread_mutex_unlock(&m);
}

void *child(void *arg) {
    printf("child\n");
    thr_exit();
    return NULL;
}

void thr_join() {
    Pthread_mutex_lock(&m);
    while (done == 0)
        Pthread_cond_wait(&c, &m);
    Pthread_mutex_unlock(&m);
}

int main() {
    printf("parent: begin\n");
    pthread_t p;
    Pthread_create(&p, NULL, child, NULL);
    thr_join();
    printf("parent: end\n");
    return 0;
}
```

- Why the parent use a `while` loop instead of an `if` statement:
  - Sometimes a thread can be spuriously woken up without any signal actually being sent.
  - A signal can wake up several threads. Another thread may have grab the mutex first and change the condition back.
- Do we need to call `signal()` before releasing the lock:
  - Technically no. But it's best practice.
  - Enable **wait morphing** optimization, where the OS moves a waiting thread directly from the condition variable's wait queue to the mutex's wait queue.
  - Without **wait morphing**: The woken thread wakes up, realizes the mutex is still hold (by the signaling thread), and go to sleep again on the mutex queue -> waste context switch.

## Broken approach: no state variable `done`

```c
void thr_exit() {
    Pthread_mutex_lock(&m);
    Pthread_cond_signal(&c);
    Pthread_mutex_unlock(&m);
}

void thr_join() {
    Pthread_mutex_lock(&m);
    Pthread_cond_wait(&c, &m);
    Pthread_mutex_unlock(&m);
}

// ...
```

- Imagine the case where the child runs first and calls `thr_exit()`. The child will signal, but there is no thread asleep on the condition. When the parent runs, it will wait and be stuck.

## Broken approach: don't hold lock when signal and wait, use `if` instead of `while` to check condition

```c
void thr_exit() {
    done = 1;
    Pthread_cond_signal(&c);
}

void thr_join() {
    while (done == 0)
        Pthread_cond_wait(&c, &m);
}

// ...
```

- Race condition: The parent calls `thr_join()`, sees that `done == 0`, and tries to go to sleep. But just before it goes to sleep, the parent is interrupted, and the child runs. The child exits, update `done = 1` and signals, but no thread is waiting and thus no thread is woken. When the parent runs again, it sleeps forever.

# Producer/Consumer (Bounded Buffer) problem

- Producer threads generate data items and place them in a buffer. Consumer threads grab items from the buffer and process them.
- Examples:
  - In a multi-threaded web server, a producer puts HTTP request into a work queue, consumer threads take requests out of the queue and process them.
  - When piping the output of 1 program into another (`grep foo file.txt > wc -l`): This runs 2 processes concurrently. `greps` writes lines from `files.txt` with the string `foo` to what it thinks is standard output. The Unix shell redirects the output to a Unix pipe. The other end of the pipe is connected to the standard input of `wc` process. -> `grep` process is producer, `wc` process is consumer, between them is an in-kernel bounded buffer.
- The bounded buffer is a shared resource -> require synchronized access.

## Broken solution

```c
int buffer; // use a single integer as the shared buffer
int count = 0; // 0 -> empty; 1 -> filled

void put(int value) {
    assert(count == 0);
    count = 1;
    buffer = value;
}

void get() {
    assert(count == 1);
    count = 0;
    return buffer;
}

// =====

int loops; // must initialize somewhere
cond_t cond;
mutex_t mutex;

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        if (count == 1) // wait for the buffer to be empty
            Pthread_cond_wait(&cond, &mutex);
        put(i);
        Pthread_cond_signal(&cond);
        Pthread_mutex_unlock(&mutex);
    }
}

void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        if (count == 0) // wait for the buffer to be full
            Pthread_cond_wait(&cond, wait);
        int tmp = get();
        Pthread_cond_signal(&cond);
        Pthread_mutex_unlock(&mutex);
        print("%d\n", tmp);
    }
}
```

- The code will work with a single producer and a single consumer.

## 1st problem

- Assume there are 2 consumers (Tc1, Tc2) and 1 producer (Tp).
- Flow:
  - 1st, Tc1 runs, acquires the lock, sees that buffer is empty, then waits.
  - Then Tp runs, acquires the lock, sees that buffer is not full, goes ahead and fills the buffer, then signals that a buffer slot has been filled. This moves Tc1 from sleeping on a condition variable to the ready queue. Tc1 is now able to run (but not yet running). The producer continues until the buffer is full, then sleeps.
  - Tc2 sneaks in and consumes the value in the buffer _(skipping the wait since the buffer is not empty)_.
  - Now Tc1 runs _(re-acquires lock before returning from the wait)_. It then calls `get()`, but there're nothing to consume. An **assertion error** is triggered.
- Cause: After the producer woke Tc1, but before Tc1 ran, the state of the bounded buffer changed (due to Tc2).
- **Mesa semantic**: Signaling a thread only wakes them up. It is just a **hint** that the state has changed, but there is no guarantee that when the woken thread runs, the state will be as desired.
  -> Most systems employ Mesa semantic.
- **Hoare semantic**: Provides a strong guarantee that the woken thread will run immediately upon being woken.
  -> Harder to build.

## Better, Still Broken: use `while`, not `if`

```c
int loops; // must initialize somewhere
cond_t cond;
mutex_t mutex;

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == 1) // if -> while
            Pthread_cond_wait(&cond, &mutex);
        put(i);
        Pthread_cond_signal(&cond);
        Pthread_mutex_unlock(&mutex);
    }
}

void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == 0) // if -> while
            Pthread_cond_wait(&cond, wait);
        int tmp = get();
        Pthread_cond_signal(&cond);
        Pthread_mutex_unlock(&mutex);
        print("%d\n", tmp);
    }
}
```

- Explain: When Tc1 wakes up and immediately rechecks the state of the shared variable. If the buffer is empty at that point, it simply goes back to sleep.
- Extra reason to use `while` - **spurious wake-up**:
  - thread can be woken up when there's no signal.
  - 1 single signal can wake up multiple threads.

## 2nd problem: there's only 1 condition variable

- Flow:
  - 2 consumers (Tc1 and Tc2) run 1st and both go to sleep.
  - Tp runs, puts a value in the buffer, and wakes 1 consumer (say T1). The buffer is now full. Tp goes to sleep.
  - Tc1 wakes up by returning from `wait()`, rechecks the condition, see that the buffer is full, consumes the value. It then signals on the condition, waking 1 sleeping thread.
  - Because Tc1 has emptied the buffer, it should wake Tp. However, if it wakes Tc2 (possible), we have a problem. Tc2 will wake up, see that the buffer is empty, and go back to sleep. Tp is left sleeping. Tc1 also goes back to sleep -> All 3 threads are left sleeping.
- Signaling must be more directed. A consumer should not wake other consumers, only producers, and vice versa.

## Single buffer producer/consumer solution

- Use 2 condition variables instead of 1.
  - Producer threads wait on the condition `empty`, and signal `fill`.
  - Consumer threads wait on the condition `fill`, and signal `empty`.
- Problem solved: a consumer can never wake a producer, and vice versa.

```c
int loops; // must initialize somewhere
cond_t empty, fill;
mutex_t mutex;

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == 1)
            Pthread_cond_wait(&empty, &mutex); // wait `empty`
        put(i);
        Pthread_cond_signal(&fill); // signal `fill`
        Pthread_mutex_unlock(&mutex);
    }
}

void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == 0)
            Pthread_cond_wait(&fill, wait); // wait `fill`
        int tmp = get();
        Pthread_cond_signal(&empty); // signal `empty`
        Pthread_mutex_unlock(&mutex);
        print("%d\n", tmp);
    }
}
```

## Correct producer/consumer solution

- Add more buffer slots, so that multiple values can be produced/consumed before sleeping.
  - With a single producer and consumer, this reduces context switches.
  - With multiple producers and consumers, this allows concurrent producing and consuming to take place, thus increasing concurrency.
- A producer only sleeps if all buffer slots are currently filled. A consumer only sleeps if all buffer slots are currently empty.

```c
int buffer[MAX];
int fill_ptr = 0;
int use_ptr = 0;
int count = 0;

void put(int value) {
    buffer[fill_ptr] = value;
    fill_ptr = (filter_ptr + 1) % MAX;
    count++;
}

int get() {
    int tmp = buffer[use_ptr];
    use_ptr = (use_ptr + 1) % MAX;
    count--;
    return tmp;
}

// =====

int loops; // must initialize somewhere
cond_t empty, fill;
mutex_t mutex;

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == MAX) // only wait if all buffer slots are filled
            Pthread_cond_wait(&empty, &mutex);
        put(i);
        Pthread_cond_signal(&fill);
        Pthread_mutex_unlock(&mutex);
    }
}

void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex);
        while (count == 0) // only wait if all buffer slots are empty
            Pthread_cond_wait(&fill, wait);
        int tmp = get();
        Pthread_cond_signal(&empty);
        Pthread_mutex_unlock(&mutex);
        print("%d\n", tmp);
    }
}
```

# Covering condition

- Example: a simple multi-threaded memory allocation library

```c
// how many bytes of the heap are free?
int bytesLeft = MAX_HEAP_SIZE;

cond_t c;
mutex_t m;

void *allocate(int size) {
    Pthread_mutex_lock(&m);
    while (bytesLeft < size)
        Pthread_cond_wait(&c, &m);
    void *ptr = ...; // get memory from heap
    bytesLeft -= size;
    Pthread_mutex_unlock(&m);
    return ptr;
}

void free(void *ptr, int size) {
    Pthread_mutex_lock(&m);
    // ... return memory to heap
    bytesLeft += size;
    Pthread_cond_signal(&c); // whom to signal?
    Pthread_mutex_unlock(&m);
}
```

- The code does not since the thread waking other threads don't know which thread(s) to wake up.
- Scenario:
  - Assume there are 0 bytes free.
  - Ta calls `allocate(100)`, Tb calls `allocate(10)`. Both wait on the condition and go to sleep.
  - Then Tc calls `free(50)`. Unfortunately, when it calls signal to wake a waiting thread, it might not wake Tb, which is only waiting for 10 bytes to be freed.
- Solution: Replace `signal()` with `broadcast()`, which wakes up all waiting threads.
  - Downside: Negative performance impact _(wake up many threads shouldn't yet be awake)_.
- The condition in this case is called a **covering condition**.
