# Types of allocated memory

- **stack** memory: managed implicitly by the compiler.
- **heap** memory: handled explicitly by the programmer.

```c
void func() {
    int *x = (int *) malloc(sizeof(int));
}

/*
- Both stack and heap allocation occur:
  . The compiler makes room for a pointer to an integer.
  . malloc() requests space for an integer on the heap,
    returns the address of that integer (or NULL on failure),
    which is then stored on the stack.
*/
```

# Library calls: `malloc()` and `free()`

- `sizeof` macro:

```c
int *x = malloc(10 * sizeof(int));
printf("%d\n", sizeof(x)); // 4 or 8 (size of pointer)

int x[10];
printf("%d\n", sizeof(x)); // 10 (size of array)
```

# Common errors

- **Forget to allocate memory**:

```c
char *src = "hello";
char *dst; // unallocated
strcpy(dst, src); // segfault and die

// Fix:
char *src = "hello";
char *dst = (char *)malloc(strlen(src) + 1); // + 1 for '\0'
strcpy(dst, src);

// Alternative: use strdup()
```

- **Not allocating enough memory (buffer overflow)**:

```c
char *src = "hello";
char *dst = (char *)malloc(strlen(src)); // lack space for '\0'
strcpy(dst, src); // still success, but may overwrite another variable
```

- **Forget to initialized allocated memory**

- **Forget to free memory (memory leak)**:
  - Still a problem for garbage-collected language: if we have a reference to some chunk of memory, the garbage collector will not free it.
  - When the process dies, the OS will clean up its allocated pages and no memory leak will take place. But freeing unused memory explicitly is a good habit.

- **Free memory before we are done with it (dangling pointer)**:

```c
int *ptr = malloc(sizeof(int));
free(ptr);

// - ptr still points to the old address.
// - subsequent use may crash program or overwrite valid memory
//   (malloc() may have recycled the freed memory).
*ptr = 42;
```

- **Free memory repeatedly (double free)**

- **Call `free()` incorrectly**: should only pass in pointers received from `malloc()`.

# Underlying OS support

## System calls

- `brk()`:
  - change the location of the program's **break** (end of heap)
  - takes 1 argument (address of the new break) -> increase or decrease the size of the heap
- `sbrk()`:
  - is passed an increment (size to add)
- `mmap()`:
  - Create an anonymous memory region within the program (not associated with any particular file but rather with **swap space**). This memory can then be treated like a heap and managed as such.
  - Also support file-backed mapping.
