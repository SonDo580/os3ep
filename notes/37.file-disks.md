- **Hard disk drives** have been the main form of persistent data storage in computer systems for decades.

# The interface

- We can view the disk as an array of **sectors** (512-byte blocks). 0 to n - 1 is the **address space** of the drive.
- Multi-sector operations are possible:
  - Many file systems will read or write 4KB (or more) at a time.
  - However, the drive manufacturers only guarantee that a single sector write is **atomic**. If an untimely power loss occurs, only a portion of a large write may complete (a **torn write**).
- Accessing contiguous blocks is much faster than any random access pattern.

# Basic geometry

- A disk has 1 or more **platters**, a circular hard surface on which data is stored persistently by inducing magnetic changes to it. Each platter has 2 sides, each of which is called a **surface**.
- The platters are bound together around a **spindle**, which is connected to a motor that spins the platters around (while the drive is powered on) at a fixed rate. The rate of rotation is often measured in **RPM (rotation per minute)**.
- Data is encoded on each surface in concentric circles of sectors. 1 such concentric circle is called a **track**.
- To read and write the surface, we need a mechanism that allows us to sense the magnetic patterns on disk or to induce a change in them. This is accomplished by the **disk head**. There is 1 head per surface. The disk head is attached to a **disk arm**, which move across the surface to position the head over the desired track.

# A simple disk drive

## Single-track latency: Rotational delay

- If already on the desired track, the drive waits for the desired sector to rotate under the disk head.

## Multiple tracks: Seek time

- The drive may first have to move the disk arm to the correct track (a **seek**):
  - Detailed phases: acceleration _(the arm gets moving)_, coasting _(the arm moves at full speed)_, deceleration _(the arm slows down)_, settling _(the head is carefully positioned over the correct track)_.
  - The **settling time** is often quite significant, as the drive must be certain to find the right track.
- When the desired sector passes under the head, the **transfer** will take place.
- Complete I/O time: seek + rotational delay + transfer.

## Other details

- **Track skew**:
  - To make sure sequential reads can be properly serviced when crossing track boundaries.
  - Without it, when the head be moved to the next track, the desired next block would have rotated past.
- **Multi-zoned** disk drives:
  - A zone is a set of consecutive tracks. Each zone has the same number of sectors per track. Outer zones have more sectors than inner zones _(a result of geometry)_.
- **Cache** (**track buffer**):
  - The cache is some small amount of memory (8 to 16 MB) which the drive can use to hold data read from or written to disk.
  - Read: The drive may decide to read in all sectors on that track and cache them, allowing it to quickly respond to subsequent requests to the same track.
  - Write: The drive can acknowledge the write has completed when it has put data in its memory (**write back** / **immediate reporting**), or after the write has actually been written to disk (**write through**).
  - Write back caching makes the drive appear faster, but can be dangerous _(For example, if the file system or applications required that data be written to disk in a certain order for correctness)_.

# I/O time

- I/O time: `T_io = T_seek + T_rotation + T_transfer`
- Rate of I/O: `R_io = Size_transfer / T_io`
  - This is often used for comparison between drives.
- Drive market:
  - performance.
  - capacity.
- There's a huge gap in drive performance between random and sequential workload.

# Disk scheduling

- The OS has played a role in deciding the order of I/O requests issued to the disk, with the **disk scheduler**.
- Unlike job scheduling, where the length of each job is usually unknown, with disk scheduling, we can make a good guess at how long a disk request will take.
- By estimating the seek and rotational delay, the disk scheduler can greedily pick the one that will take the least time to service first.

## SSTF (shortest seek time first) / SFF (shortest seek first)

- Orders the queue of I/O requests by track, picking requests on the nearest track (to the head) to complete first.
- Problem 1: The drive geometry is not available to the host OS.
  - Fix: Instead of SSTF, he OS implements **NBF (nearest block first)**, which schedules the request with the nearest block address next.
- Problem 2: **Starvation**.

## Avoid starvation: Elevator (SCAN or C-SCAN)

- The algorithm (**SCAN**) simply moves back and forth across the disk servicing requests in order across the tracks.
- A single pass across the disk (tracks) is called a **sweep**.
- **F-SCAN**:
  - Freezes the queue to be serviced when it is doing a sweep: Place requests that come in during the sweep into a queue to be serviced later.
  - This avoids starvation of far-away requests, by delaying the servicing of nearer-by but late-arriving requests.
- **C-SCAN (Circular SCAN)**:
  - Instead of sweeping in both directions, only sweeps from outer to inner, then resets at the outer track to begin again.
  - Why: back-and-forth scan favors the middle tracks.

## Account for rotation: SPTF (shortest positioning time first) / SATF (shortest access time first)

- Depends on the relative time of seeking as compared to rotation, it may be better to seek further.
  - If seek time is much higher than rotational delay -> use SSTF.
  - If seek time and rotational delay are roughly equivalent -> use SPTF.
- SPTF is even more difficult to implement in an OS, which does not have an idea of where track boundaries are or where the disk head currently is (in rotational sense) -> SPTF is usually performed inside a drive.

## Other scheduling issues

- Where is disk scheduling performed:
  - In older systems, the OS did all the scheduling.
  - In modern systems, disks can have sophisticated internal schedulers themselves _(which can implement SPTF accurately)_. The OS scheduler usually picks the best few requests and issues them to disk.
- **I/O merging**:
  - Example: Requests to read blocks 33 then 34 is merged into a single 2-block request.
  - Merging is important at the OS level, as it reduces the number of requests sent to the disk and thus lowers overheads.
- How long to wait before issuing an I/O to disk:
  - **work-conserving**: The OS immediately issues every single I/O request to the drive.
  - **anticipatory disk scheduling** - **non-work-conserving**: Wait for a bit. A new and "better" request may arrive, thus overall efficiency is increased.
